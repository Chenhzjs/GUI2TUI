# 通用本地资源协作

日期：2026-10-09。用户授权方向：终端无法充分表达的内容交给本地应用，重点解决
资源获取和传输；不限图片、PDF。本文是新增工作的设计及验收清单，不代表已实现。

## 统一规则

按资源能力、MIME、来源和本地处理器选择路径，不按应用名称或窗口标题分支。
继续使用 ExternalModality、ReferencedResource、OriginalArtifact、RenderedSnapshot
和 LocalModalityBroker，不另造语义树。远端 GUI 仍是操作和状态的权威；本地打开
成功仅表示处理器接收了资源，不表示远端任务完成，也不自动同步本地修改。

| 内容 | 优先交付物 | 本地处理方式 | 无原资源时 |
|---|---|---|---|
| 位图、矢量图、扫描件 | 原文件或可信 URI | 图片/矢量查看器 | 已支持范围内的显式静态快照 |
| PDF、分页文档 | 原文件或公开导出文件 | 本地文档阅读器 | 保留远端翻页等语义；不把页面截图当原文档 |
| 音频、视频 | 媒体文件或可访问 URI | 本地播放器 | 实时流须独立支持，单帧不等于播放 |
| 3D、CAD、科学可视化 | 可移植资源及明确依赖 | 已配置的兼容查看器 | 单帧只用于查看；不宣称可旋转或编辑 |
| 图表、地图、画布、仪表板 | 公开资源/导出；否则静态快照 | 对应查看器 | 当前没有通用画布采集，不自动放宽 Image 采集范围 |
| 附件、演示、表格、其他文件 | 明确来源的单个文件 | 用户配置的 MIME 处理器 | 现有 MIME 白名单不支持的类型保持未支持，逐项验证后扩展 |
| 实时桌面、游戏、持续交互图形 | 实时交互通道 | 单独的远程交互模态 | 现有文件传输不具备此能力 |

类型表是覆盖需求，不是现有支持表。已有 ModalityKind 包含 Image、Document、
Video、Audio、VectorGraphic、PortableModel、LiveVisual、Unknown；具体 MIME 仍以
broker 当前实现为准。没有处理器时应允许明确说明资源可传但无法打开，不能混为获取失败。

## 获取与传输决策

1. 公开 Hyperlink/Document/Accessible 属性给出可信 URI：保留引用。
   本地能访问才交给本地处理器；远端 localhost、私网地址、登录态不等于本地可访问。
2. 同机文件或已配置的共享路径映射：打开经校验的本地路径，不传重复字节。
3. 远端有明确原文件、公开导出结果，或用户显式指定的文件：传单个 artifact，
   校验大小和 SHA-256 后交给本地处理器。用户指定文件不冒充从 GUI 自动解析的资源。
4. 只有静态画面：仅在现有显式采集能力内提供 RenderedSnapshot，标明快照及时间。
5. 无 URI、无可取得文件、无支持的采集能力：说明缺少哪一步；不猜标题路径，
   不读应用私有数据库，不利用私有 API，不把截图识别结果写回语义树。

原文件可能不含远端未保存的修改；本地副本必须标明来源，不宣称与当前 GUI 完全一致。
外部依赖、多文件资源、流媒体、编辑回传分别需要明确契约，不能当普通单文件完成。

## 当前已有与缺口

已有：F4 引用入口、同机 Unix socket broker、处理器注册、明确授权、分块接收、
长度/hash 校验、取消/超时、临时文件清理；显式 send-artifact；受限 Image 静态采集。
2026-10-09 定向运行 cargo test --lib modality::，38 项通过。这不证明跨主机可用。

缺口：自动原资源获取、TUI 原文件传输入口、跨主机传输验证、资源依赖处理、
更广 MIME、本地修改回传。跨主机资源传输不需要先实现远端 AT-SPI 语义协议；
优先复用现有 artifact 数据通道，通过用户配置的 SSH 通道连接本地 broker。
SSH Unix socket 转发尚未实现/验证为受支持部署，不把示意命令写成可用能力。
原计划推迟 Remote Companion 的约束继续适用于跨主机语义控制，不阻止本次授权的资源传输研究。
