# GUI2TUI v0.7 Deployment & Environment Completeness Roadmap

This roadmap is derived from the
[v0.7 Discovery](v0.7-deployment-environment.md). Discovery, 0.7A and 0.7B are
complete. 0.7C has completed all evidence available in the current environment
but remains partially validated because real local X11 and SSH PTY environments
were unavailable. Every later phase remains planning, not implementation
authorization. Completing available work does not authorize the next phase,
milestone qualification, 1.0 integration, a version change, an RC, a tag, or
a release.

recommended 1.0 baseline. Most work is explicit session selection, bounded
diagnosis, installation completeness and real-environment qualification.

## 2. Discovery conclusion

The current process connects to the session D-Bus, obtains the accessibility
bus from `org.a11y.Bus`, enumerates current AT-SPI applications and creates
exact application authority from a current selection. The model is local to a
graphical user's host/session. X11 is not part of semantic authority; it is a
display environment and, separately, a requirement of the optional static
visual provider.

The user-approved 1.0 development direction is:

- local Linux X11 is a core support target;
- managed Xvfb/headless is a core support target and reuses the existing
  helper rather than a general desktop/session manager;
- native Wayland and XWayland are separate priority validation targets, with a
  goal of inclusion when real evidence supports it;
- same-host SSH TUI should be pursued for inclusion by reusing the selected
  same-user session and existing terminal lifecycle; and
- cross-host local-TUI/remote-GUI operation and Remote Companion are deferred
  until after 1.0.

Selected Ubuntu GNU/Linux versions, native x86_64/aarch64 archives and a
documented terminal contract remain the packaging/deployment baseline to be
qualified in later phases. These are development targets, not current formal
support claims. Native Wayland, XWayland, real local X11 and SSH PTY still
require their named evidence phases.

## 4. 0.7A — Environment Contract and Session Selection

**Status: COMPLETE / VALIDATED.**

The prior behavior loaded a valid persistent descriptor at both user-facing
entry points before connection, overwriting inherited `DISPLAY`, session bus
and session type. `GUI2TUI_NO_MANAGED_SESSION` was the only opt-out, and
Doctor did not report which topology it had probed. This could expose the
managed registry while the user expected the current desktop.

The implemented contract is:

- `--session desktop` uses only the inherited current desktop/session
  environment. It never reads or applies the managed descriptor.
- `--session managed` requires the existing current-user private descriptor.
  Missing, invalid, stopped or unsafe state fails before connection; an
  unreachable selected bus fails at the connection probe. There is no desktop
  fallback and no automatic session creation.
- With no flag, compatibility mode honors `GUI2TUI_NO_MANAGED_SESSION`, then
  reuses a valid managed descriptor if present, otherwise uses the inherited
  environment. Invalid/stale descriptor state produces a visible warning and
  uses the inherited environment; GUI2TUI does not delete the file.
- Selection is applied before Tokio or D-Bus initialization and is inherited
  coherently by private inspector/launcher children.
- Startup/inspector stderr and the Doctor `session-selection` check identify
  Current desktop or Managed headless without printing bus addresses,
  descriptor contents, application names or GUI contents.
- A healthy registry with zero applications remains a warning distinct from
  selection or connection failure.

The implementation reuses `product::headless`, the existing descriptor,
Doctor, backend connection and application selector. It adds no session
manager, deployment registry, remote component, runtime identity or second
application selector. Selection still establishes transport only. A fresh
current registry enumeration and explicit exact application choice open a new
application generation; no cache, scope, binding, command or ticket migrates
between processes/sessions.

Targeted Ubuntu 24.04 arm64 evidence used two isolated Xvfb/session-D-Bus/
AT-SPI universes owned by one unprivileged user. Explicit desktop and managed
selection, compatibility precedence, environment opt-out, zero applications,
fresh selection, one safe semantic operation, missing/invalid/stopped/unsafe/
unreachable descriptors, redaction and cleanup passed. This proves the
selection contract under controlled X11; it is not an ordinary local desktop
qualification. Real local X11 is **NOT TESTED** and remains 0.7C work.

Remote Companion deferral is approved. Exact Ubuntu/glibc package floors are
left to 0.7E rather than being inferred from historical v0.3 artifacts.

## 5. 0.7B — Installation and Diagnostic Completeness

**Status: COMPLETE / VALIDATED.**

The completed phase adds a bounded user-prefix flow without creating an
installer framework. `scripts/install-user.sh` consumes either the standard
current-source `target/release` binaries or an extracted bundle, defaults to
`$HOME/.local`, accepts an explicit absolute prefix including spaces, refuses
root/sudo, symlink directories and all existing target files, and installs the
existing `bin`/`libexec/gui2tui` layout. A private mode-0600 hash manifest and
installed `uninstall-user` remove only the five recorded executable/script
files plus that manifest. Changed files, managed-path symlinks, unsafe manifest
metadata and an existing Managed descriptor fail closed; unrelated prefix
entries, XDG configuration, runtime data and private recovery candidates are
preserved.

Helper lookup now lives in the existing product path layer and requires an
executable file. Installed paths are resolved relative to the running
`gui2tui`; Cargo siblings and the bounded source `headless-session` fallback
remain developer-only compatibility. Doctor uses that same resolution for the
main entry, required inspector, Managed helper, optional same-host modality
helper and exact-file uninstaller. No checkout, Cargo or current-working-
directory assumption remains in the installed path.

The existing Doctor report/schema now separates installation, TTY/PTY,
`TERM`, UTF-8, dimensions, session D-Bus, `org.a11y.Bus`, AT-SPI registry,
zero/current applications and application-semantic qualification. Stateful
raw/alternate-screen/enhanced-key probing is explicitly NOT CHECKED to avoid
changing the terminal. Application presence never becomes a platform or
capability claim. The optional complex-text handler is structurally loaded and
resolved as an executable without spawning it or creating a candidate; absence
is valid and an unavailable configured handler is a feature-local warning.

Ubuntu 24.04 arm64 live evidence installed into an isolated prefix containing
a space, ran from `/` and `/tmp`, located all helpers, exercised Desktop and
Managed Xvfb Doctor, a controlled PTY, zero/current applications, unavailable
session bus, handler states and one existing authoritative semantic operation,
then proved active-Managed and symlink uninstall refusal plus safe removal and
configuration/unrelated-file preservation. AT-SPI address failure was not
reliably constructed and is **NOT TESTED live**; its bounded branch is source-
checked. The Desktop evidence used controlled Xvfb, not a real local X11
desktop. No package/ABI, SSH, Wayland or broad terminal qualification ran.

No DeploymentManager, EnvironmentRegistry, daemon, updater, package manager,
automatic dependency installation or semantic scan was added. Detailed
evidence is in
[`installation-diagnostics/HANDOFF.md`](../validation/v0.7/installation-diagnostics/HANDOFF.md).

## 6. 0.7C — X11, Headless and Same-host SSH Qualification

**Status: PARTIALLY VALIDATED / ENVIRONMENT EVIDENCE PENDING.**

**Goal:** Qualify the non-Wayland same-host deployment rows through a small
continuous real-environment matrix.

**Evidence:** Ubuntu 24.04 arm64 Xvfb has extensive functional evidence and a
current-source Doctor probe. Ordinary local X11 and interactive SSH PTY use
have no complete current qualification.

**Scope:**

- install and first-run in one ordinary local X11 desktop;
- create/reuse/stop the managed Xvfb session and verify process cleanup;
- attach through an SSH PTY to an existing desktop session and to the managed
  session as appropriate to the approved contract;
- verify application discovery/selection, one representative semantic
  operation, events/refresh, terminal resize/suspend/exit, direct-argv external
  handoff and final terminal usability;
- exercise wrong-session/wrong-user/missing-session refusal without copying
  credentials; and
- record bounded process, FD, reader and artifact ownership.

**Non-goals:** broad application matrix, performance soak, remote desktop
matrix, cross-host GUI access, new session manager, terminal UI redesign.

**Reuse:** v0.6 runtime/terminal evidence, existing GTK/Qt fixtures, Doctor,
launcher, headless helper, PTY helpers and resource diagnostics.

**Required live environment:** approved Ubuntu X11 desktop, Xvfb/session D-Bus
environment and an actual SSH client/server PTY path on the same host/user
model.

**Hard exit conditions:**

1. Each declared row has a reproducible install-to-operation-to-exit record.
2. Existing and managed sessions never silently merge application universes.
3. SSH uses one terminal reader, restores supported terminal state and handles
   external handoff coherently.
4. Completed helpers/handlers are reaped and managed-session stop leaves no
   owned daemon/process leak.
5. Exact application authority and private artifact rules remain unchanged.
6. Any topology without complete evidence remains Limited or Not Tested.

### Available-environment result

Ubuntu 24.04 aarch64 under OrbStack supplied Xvfb, private session D-Bus,
AT-SPI, GTK fixtures and a local PTY. A current-source release build was
installed into an isolated unprivileged prefix and used outside the checkout.
Managed Xvfb passed create, current descriptor selection, Doctor, fresh
application selection, dynamic Action/readback, refreshed-scene continuation,
normal terminal restoration, reconnection, stop, exact child cleanup,
recreation, a positive external-handler writeback/readback and safe uninstall.
Two controlled Xvfb registries also proved explicit Desktop/Managed isolation,
including same-named applications and refusal to migrate a stopped Managed
view to Desktop. Managed Xvfb is therefore **QUALIFIED** on that recorded
topology.

The guest had no running normal Linux X11 desktop, Xorg/display-manager
session or local X11 socket. It also had no `sshd`, SSH service or listening
SSH endpoint. No service was installed or enabled. Consequently real local
X11, SSH -> Existing Desktop and SSH -> Managed Headless remain **NOT TESTED**.
The local PTY and controlled Desktop Xvfb evidence are not substitutes. 0.7C
as a whole cannot be marked fully qualified. Detailed evidence is in the
[0.7C handoff](../validation/v0.7/x11-headless-ssh/HANDOFF.md).

## 7. 0.7D — Wayland and XWayland Qualification

**Goal:** Establish the actual native-Wayland and XWayland support level from
real public Accessibility evidence.

**Evidence:** The semantic backend is AT-SPI/D-Bus and display-server neutral;
geometry is requested through AT-SPI and has safe presentation fallbacks.
Static visual capture is native-X11 only. No real Wayland session has been
tested.

**Scope:**

- run in a real Wayland desktop and identify native versus XWayland apps;
- validate session/accessibility-bus discovery, GTK and Qt application
  enumeration, public tree, events, modal/scope behavior and one exact verified
  operation;
- record AT-SPI screen extents and prove missing/inconsistent geometry degrades
  only presentation;
- verify external text terminal handoff is independent of compositor;
- confirm static visual capture reports unavailable rather than guessing; and
- set the final Supported/Limited/Not Tested/Unsupported status for each row.

**Non-goals:** screen capture protocol, compositor plugin, OCR, input
injection, toolkit adapters, headless Wayland, X11 emulation or semantic
backend rewrite without a separately reviewed reproduced blocker.

**Reuse:** current AT-SPI backend, spatial evidence/fallback, flat layout,
Doctor, current-tree refresh, existing GTK/Qt fixtures and terminal lifecycle.

**Required live environment:** a real maintained Wayland desktop with a native
GTK app, a native Qt app where available, and a separately confirmed XWayland
app. X11/Xvfb does not substitute.

**Hard exit conditions:**

1. Native and XWayland evidence is labelled separately.
2. Current public semantics, exact authority and fresh readback work at the
   declared support level.
3. Missing/untrusted geometry never changes semantic correctness and leaves a
   usable fallback presentation.
4. Unsupported static capture fails explicitly.
5. The final contract claims no more than the observed environments.

## 8. 0.7E — Package and Environment Contract Qualification

**Goal:** Qualify the approved environment contract and current source as one
deployment product baseline before the separate milestone close.

**Evidence:** v0.3.0 has historical two-architecture build/smoke evidence, but
current source cannot inherit that result. Earlier functional/runtime
milestones are already qualified and should receive representative regression,
not a full rerun.

**Scope:**

- produce internal native x86_64 and aarch64 archives from the fixed candidate
  source using the existing pipeline;
- check archive layout, helper discovery, dynamic dependencies and declared
  glibc ceiling;
- perform fresh-prefix install/Doctor/start/representative operation/exit on
  each candidate-supported environment and architecture available in the
  approved matrix;
- run one integrated environment failure/recovery path and representative
  v0.6 authority/terminal/privacy regression;
- finalize support, limitation, installation and troubleshooting documents;
  and
- record P0/P1 and exact untested/deferred rows for Milestone Qualification.

**Non-goals:** public RC, GitHub Release, public-download campaign, signing,
attestation, new package format, v1.0 integration, new application features.

**Reuse:** release workflows/scripts, ABI scanner, archive smoke, prior live
fixtures, Doctor and v0.6 validation helpers.

**Required live environment:** native or approved-equivalent Ubuntu x86_64 and
aarch64 package workers plus every row ultimately labelled Supported. Limited
rows receive only their expressly declared evidence.

**Hard exit conditions:**

1. Current-source packages for approved architectures meet layout, ABI and
   fresh-install checks.
2. Every Supported row has matching real environment evidence; every other
   row is labelled accurately.
3. Install, session selection, diagnosis, representative operation, external
   handoff and terminal exit compose successfully.
4. Configuration and artifacts retain current privacy/ownership guarantees.
5. No stale authority, display-derived authority or environment-specific
   semantic branch appears.
6. P0 = 0 and P1 = 0 for the approved contract.

## 10. v0.7 milestone qualification gates

The milestone can close only when:

- the environment contract is approved and represented accurately in product
  documentation;
- approved install and first-run flows work without root;
- the intended graphical/accessibility session is selected explicitly;
- Doctor gives safe, useful distinctions for supported topology failures;
- current application enumeration and user selection remain the only path to
  semantic application authority;
- every Supported X11/headless/SSH/Wayland row has its required live evidence;
- terminal and external-handler ownership remain correct in each claimed
  terminal topology;
- current packages for each claimed architecture have reproducible layout,
  ABI and install evidence;
- configuration, reports and artifacts preserve privacy and permissions;
- untested, experimental and deferred environments are not described as
  Supported;
- representative v0.4-v0.6 semantic/runtime behavior remains intact; and
- P0 = 0 and P1 = 0.

Milestone close remains a separately authorized documentation/evidence review.

## 11. Stable constraints carried into every phase

- Semantic authority remains `RuntimeSessionId` +
  `ApplicationGenerationId` + exact `BackendLocator`, further constrained by
  current scope, capability, ticket and authoritative readback.
- Display, PID, user-visible name, geometry, environment variables and session
  metadata never grant or migrate operation authority.
- Current public Accessibility structure, not cache residency or incomplete
  event history, establishes a full-refresh baseline.
- Transport/session recovery restores communication and requires fresh
  application selection; it does not revive bindings.
- External handlers and artifacts never extend semantic target authority.
- PasswordText is never exported. Private owned paths remain 0700/0600 and
  bounded.
- Terminal input has one current reader; supported handoff, suspension and
  exit paths preserve terminal ownership.
- No toolkit/app branch, private API, OCR, GUI input injection, coordinate
  clicking, file-system semantic bypass, shell expansion or fuzzy target match.

## 12. Decisions and remaining authorization

Resolved in 0.7A:

1. Local Linux X11 and managed Xvfb are core 1.0 support targets.
2. Native Wayland/XWayland remain separate evidence-driven priority targets.
3. Same-host SSH TUI should be pursued for inclusion.
4. Cross-host Remote Companion is deferred until after 1.0.

Remaining evidence decisions:

1. Choose the exact Ubuntu/glibc baseline during package qualification.
2. Set final SSH status from 0.7C evidence.
3. Set native Wayland and XWayland status separately from 0.7D evidence.

The next recommended direction is to supply an approved real local Ubuntu X11
desktop and a safe same-host SSH client/server PTY environment, then complete
the missing 0.7C rows. 0.7D–0.7E and milestone close remain unauthorized; no
phase starts automatically.
