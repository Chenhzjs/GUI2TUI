# GUI2TUI v0.6 Runtime Continuity & Multi-Surface Robustness Discovery

## 1. Discovery status

Discovery ran from qualified v0.5 HEAD
`1a94f85e85615bf8b479111566779ce3703a25bf` on branch
`v0.6/runtime-continuity-multi-surface`. Production source and permanent tests
were not changed.

**Conclusion: A — EXISTING AUTHORITY MODEL SUFFICIENT; BOUNDED RUNTIME
HARDENING REQUIRED.**

The current composition of `RuntimeSessionId`, `ApplicationGenerationId`, and
exact `BackendLocator` is sufficient to express runtime authority over time.
No new epoch, surface, window-manager, task, or workflow identity is justified.
The missing work is bounded lifecycle policy and ownership hardening around
transport recovery, old asynchronous work, retained UI history, and terminal
and external-handler cleanup.

The candidate stable principle is:

> Time must not transfer authority. A process, surface, event, result, focus,
> or object that appears next never inherits authority from what preceded it.

This is a Discovery result, not yet a permanent implemented v0.6 contract.

## 2. Evidence method

Source inspection covered the actual runtime, AT-SPI backend, event producer,
semantic and content caches, operation observers, scene and palette bindings,
scope/focus restoration, external text, external modality, artifacts, signals,
and terminal owner. Live evidence ran on the established Ubuntu 24.04 arm64
OrbStack guest in an isolated Xvfb/X11, session D-Bus, and AT-SPI environment.

The bounded live work comprised:

- five same-name Qt application generations in one GUI2TUI process;
- a real AT-SPI launcher/bus kill, bounded failed retries, and fresh recovery;
- same-process exact W1-to-W2 replacement and simultaneous-window scope;
- twenty modal create/close cycles with cache, RSS, thread, FD, and queue
  observations;
- application replacement while an exact public action call was blocked;
- a configured external text handler returning after same-name app
  replacement;
- terminal detach/reattach, four resizes, and SIGTERM restoration;
- targeted existing tests for runtime tickets, event overflow, and owned
  artifact recovery.

Temporary validation-only probes were removed after capture. No full Rust
suite, broad task corpus, soak campaign, or production feature was run.

## 3. Current runtime and lifetime model

The actual ownership model is:

```text
GUI2TUI process / terminal owner
└── RuntimeSessionId                         one TUI runtime lifetime
    ├── AT-SPI backend connection            replaceable transport
    ├── ApplicationGenerationId              one selected app-instance epoch
    │   ├── exact application BackendLocator
    │   ├── SemanticCache / ContentRuntime
    │   ├── current InteractionScopes
    │   ├── TuiScene / SceneBindings
    │   ├── event subscription for app bus
    │   └── bounded operation tickets/tasks
    ├── terminal attach state
    └── external-modality endpoint state
```

`TuiApplication::open_fresh_generation` replaces the cache, content, scene,
scopes, commands, choices, event receiver, focus, and transient UI state while
moving the same `RuntimeSession` into the replacement application object. A
healthy AT-SPI connection can therefore span application generations without
making any old application object current.

`TuiApplication::reconnect_backend` already performs four bounded connection
attempts after 100/200/400/800 ms. A successful attempt constructs an entirely
fresh application view, invalidates the old application, increments the
application generation, and keeps the same runtime session. A continued outage
stops retrying, retains only a read-only stale view, and offers explicit F5 or
application selection.

## 4. Identity-layer inventory

| Identity | Creation and normal survival | Invalidation | Authority role | Restart/reconnect behavior |
| --- | --- | --- | --- | --- |
| `RuntimeSessionId` | Created with `RuntimeSession`; survives refresh, app generation changes, and current reconnect | GUI2TUI runtime drop/restart | Rejects tickets from another runtime; insufficient alone | Current reconnect preserves it; a new GUI2TUI process gets a new value |
| `ApplicationGenerationId` | Incremented only after a fresh selected application/cache is opened; survives ordinary refresh and window recreation | App loss, explicit reselection, or backend loss before a new generation | Selected application-instance epoch for tickets and external text | Same-name restart and bus reconnect receive a new generation |
| `BackendLocator` | Built from a D-Bus unique bus name plus exact object path; survives only while that public object does | Object, app, or connection replacement | Exact backend object address, subject to current generation/scope/capability | Never reattached by name, position, PID, or `RuntimeNodeId` |
| `RuntimeNodeId` | Assigned in the semantic cache and may be reconciled within the same cache for presentation continuity | Fresh application cache/generation; removal without reconciliation | Focus, layout, content, and hit-testing only | Five app generations received disjoint IDs; never operation authority |
| `ContentBlockId` | Derived inside a current `ContentRuntime`; may be preserved during its catalog rebuild | Fresh content runtime/application generation | Reader presentation identity only | Rebuilt with the fresh application state |
| `SceneElementId` | Assigned while building one current scene | Every scene replacement | Local focus/render index only | Cannot locate a backend object |
| `ExternalModalityId` | Process-global monotonic ID when a modality resolution is produced | Resolution/view lifetime; process exit | Names a derived modality result, not GUI operation authority | Origin loss does not authorize a new semantic target |
| Operation ticket | Registered with exact session, application generation, operation ID, kind, and cancellation token | Completion, cancellation, application invalidation, endpoint-owner loss, shutdown | Admission and late-result isolation | Completion in another generation is `StaleIdentity` |
| `InteractionScopeId` | Wraps the current scope root `RuntimeNodeId`; scopes are rebuilt from fresh public structure | Scope/root disappearance or fresh application view | Only the current scope plus exact root locator constrains operations | Does not survive as authority across replacement |

Although the cache can reconcile `RuntimeNodeId` for presentation inside one
generation, every mutating path revalidates the exact locator, current cache,
current scope, and capability. Presentation reconciliation is therefore not a
temporal authority bridge.

## 5. Session, generation, and authority epoch decision

The evidence supports this decomposition:

```text
RuntimeSessionId
  = GUI2TUI runtime/connection-owner continuity

ApplicationGenerationId
  = currently selected application-instance authority epoch

BackendLocator
  = exact public object inside that epoch
```

Top-level window lifecycle does not require `SurfaceGenerationId`. Within one
application generation, exact changing window locators plus freshly rebuilt
`InteractionScope` correctly rejected W1 commands and admitted W2 commands.

**Identity decision: SUFFICIENT WITH SMALL LIFECYCLE HARDENING.** The hardening
is policy and resource ownership, not another identity type.

## 6. Operation tickets and cancellation

The runtime registry admits at most 32 active operations. Every registered
ticket carries session and generation. Application invalidation drains the
registry and cancels each token. `complete` rejects a wrong session, wrong
generation, already completed, absent, or cancelled ticket and counts a
rejected late result.

Background capture and modality tasks update status or artifacts only when
their ticket completes in the current registry. Application loss cancels and
aborts those tasks. Transition actions run their AT-SPI invocation in a task;
the bounded observer rechecks current authority and completion rewrites an
otherwise apparent outcome to stale/cancelled when the ticket has expired.

The targeted runtime tests passed for 20 stale generations, duplicate/late
completion, endpoint-owner cancellation, registry capacity, and shutdown.
The live blocked-action case then killed A1, started same-looking A2, observed
generation unavailable, and opened generation 2 only after explicit F5. A2
remained unchanged until a fresh operation was chosen.

Remaining gap: ticket protection is strong, but future implementation should
inventory every spawned task under one explicit owner and make shutdown/join
behavior observable. The AT-SPI event producer currently has no retained
`JoinHandle`; receiver closure makes it exit safely, but the owner cannot await
that exit.

## 7. Application restart evidence

Five bounded Qt fixture restarts kept one `RuntimeSessionId` while generations
advanced 1 through 5. The same application name, window title, and control
labels were reused. Each old process disappeared into an unavailable state;
Enter on the stale scene could not dispatch. A newly started same-name process
was not silently rebound. Explicit F5 built a fresh cache and generation, and a
fresh exact action remained usable.

Cache nodes stayed at 37 in every generation, threads at 13, FDs at 17, and
RSS moved from 18,916 KiB to 19,632 KiB during the short accelerated run. Each
generation had a distinct focused `RuntimeNodeId`.

```text
APP_RESTART_OLD_AUTHORITY_REFUSED=PASS
APP_RESTART_FRESH_AUTHORITY_AVAILABLE=PASS
APPLICATION_GENERATION_RESTART_BOUNDARY=PASS
```

Object-path reuse was not observed and was not forced. Correctness did not
depend on its absence because the bus unique name and generation are also
required.

## 8. Window recreation and multi-surface evidence

A temporary controlled Qt process destroyed W1 and created semantically
similar W2 with the same title and control names. The application generation
remained 1, as expected. The target locator changed. A command-palette binding
frozen on W1 was refused and did not mutate W2; a fresh W2 binding worked.

The same fixture exposed two simultaneous top-level windows. An exact public
focus action moved current presentation evidence to the secondary window;
fresh scope analysis selected that window as active and excluded the
background command. After the secondary closed, the main window again became
current. No window registry or new surface identity was required.

The current product does not promise a dedicated window switcher; current
authority follows fresh supported focus/scope evidence. Broader user-facing
multi-window movement should be decided during bounded v0.6 work, not inferred
from names or window order.

```text
WINDOW_RECREATION_STALE_AUTHORITY_REFUSAL=PASS
WINDOW_RECREATION_FRESH_RECOVERY=PASS
MULTI_WINDOW_CURRENT_AUTHORITY=PASS
```

## 9. Application switching

Source inspection shows that explicit selection calls `application_gone`
first, clearing the old generation, operations, overlays, reader, edit state,
palette, artifacts, and hit map. It then creates a fresh generation from the
selected current application. The normal `b` selector is currently offered
from unavailable state; arbitrary simultaneous multi-application control is
not a v0.6 requirement.

A distinct A-to-B live selector sequence was not needed for the authority
decision and was not run. It remains required evidence for the recovery phase.

```text
APP_SWITCH_OLD_BINDING_REFUSAL=NOT_TESTED
APP_SWITCH_FRESH_BINDING_RECOVERY=NOT_TESTED
```

## 10. In-flight operation evidence

An exact current `Slow action` entered a deliberately blocked public action
call in A1. While its transition ticket and invocation were active, A1 was
terminated and same-looking A2 started. The current runtime invalidated the
application rather than accepting the old call against A2. A2 showed its
initial state. Explicit F5 opened generation 2; a fresh action then succeeded.

There was no mutation or confirmation in the new epoch and the runtime stayed
usable.

```text
INFLIGHT_OPERATION_EPOCH_ISOLATION=PASS
```

## 11. Event stream and late-event analysis

There is one bounded event subscription per selected application view. Its
producer filters D-Bus messages by the selected application's unique bus name.
The bounded MPSC queue defaults to 2,048 entries. Overflow drops the incomplete
prefix, raises one resync request, and forces a fresh full application
snapshot. The 10,000-delivery capacity-4 targeted test passed and counted all
drops without exceeding capacity.

Events can update current cache state only through exact-locator dirty scopes
and current backend reads. Unknown, window, cache, and malformed events widen
to an application resync. Events never confirm operations. Replacing an
application object replaces its receiver; closing the old receiver wakes and
ends the old producer. Thus queued A1 events are not consumed by A2.

The long-lived rule remains sufficient with one addition: event producer
ownership must be explicit enough that recovery/shutdown can prove the old
producer has exited. No event sourcing or event correlation model is needed.

```text
OLD_EVENT_CANNOT_ESTABLISH_NEW_TRUTH=PASS
```

## 12. Bus interruption and reconnect

The isolated test killed the real AT-SPI launcher and bus children. The TUI
invalidated generation 1, entered `Degraded`, cancelled current owners, made
the scene read-only, and performed exactly four bounded attempts. It did not
busy-loop while the service remained absent for 5.167 seconds. After a new
AT-SPI bus address and fixture were established, explicit F5 created
generation 2, rejected the old locator, and a fresh action worked.

Backend errors distinguish missing desktop session, AT-SPI unavailable,
application enumeration failure, event stream failure, stale object,
operation timeout, permission failure, and semantic rejection. Normal TUI UX
intentionally compresses several transport causes into backend unavailable.

Current reconnect support is **SUPPORTED, BOUNDED**: a short outage can recover
inside the four-attempt schedule, and a longer outage requires explicit F5.
However, automatic recovery reconstructs by the prior descriptive application
selector. Because a name is not application-instance authority, future v0.6
must either prove the exact old application instance is still selectable or
require fresh user selection. A new generation prevents stale operations, but
it does not by itself prove the recovery policy chose the intended app.

```text
BUS_INTERRUPTION_SAFE_FAILURE=PASS
CURRENT_RECONNECT_SUPPORT=SUPPORTED
```

## 13. Cache lifecycle and churn

`SemanticCache` is a single-owner arena with exact locator and runtime-ID maps.
Subtree replacement removes prior entries before inserting current entries;
full application reconstruction replaces the entire cache. The content range
cache is bounded to 512 KiB and 256 ranges with LRU eviction. Content sources
removed from the semantic catalog are invalidated.

Twenty modal create/close cycles produced 366 processed events and 54 full
snapshots. The current semantic shape returned to nine nodes. TUI resources
changed from 22,960 to 23,032 KiB RSS while threads stayed 13 and FDs stayed
18. The five-generation restart probe likewise retained 37 cache nodes, 13
threads, and 17 FDs per generation. This is bounded supporting evidence, not a
long soak threshold.

Two in-generation maps lack explicit pruning or size bounds:
`recent_commands` and `scope_focus_history`. Identical modal churn did not
produce an observed leak, partly because presentation IDs can reconcile, but
unbounded unique-surface churn could retain history. They require explicit
ownership/bounds in v0.6. `full_snapshot_count` and event counters are
monotonic scalar metrics, not retained object history.

```text
CACHE_CHURN_STALE_AUTHORITY=PASS
CACHE_CHURN_GROWTH=BOUNDED
```

## 14. Repeated surface churn

Across twenty modal cycles, fresh scope analysis entered the current modal,
removed it after close, and returned to the main window. No stale binding was
usable, the event queue drained, current operations remained available, and
the cache/resource observations above stayed approximately at baseline.

```text
REPEATED_SURFACE_CHURN_CORRECT=PASS
```

## 15. External handler lifecycle

An external text session captures the exact target `RuntimeNodeId`, locator,
application generation, scope, original complete text, and operation ticket.
The configured handler edits only a private 0600 candidate in a 0700 owned
namespace while the real terminal is detached.

In the live stale-return case, A1 was terminated while the handler waited and
same-looking A2 was started before the modified candidate returned. GUI2TUI
rechecked app availability, generation, exact locator, capability, scope, and
fresh GUI value. A2 retained its original text; the candidate was not written
to it. The modified candidate was preserved privately for user recovery.

Normal unchanged/success/failure drops the leased temporary directory. A
conflict or stale modified candidate is intentionally preserved; the next
startup's marker/UID/link/lease-validated recovery reclaims abandoned owned
namespaces. The targeted recovery test passed. The namespace is limited to 256
files and TTL metadata is capped at 1,800 seconds, though cleanup is startup-
driven rather than a live periodic reaper.

```text
EXTERNAL_HANDLER_STALE_WRITE_REFUSAL=PASS
```

One hardening point remains: after the final awaited backend write, external
text currently calls `runtime.complete` but discards its result. Single-threaded
dispatch prevents a new generation from being installed concurrently today,
and exact compare/write/readback protects the backend target, but v0.6 should
make ticket completion a required success condition rather than relying on
that scheduling property.

## 16. External modality lifetime

`ExternalModalityId` identifies one derived modality resolution, not an AT-SPI
object. Every acquisition/handoff starts from a current candidate with exact
owner locator and scope, uses a session/generation ticket, and revalidates the
candidate before publishing an artifact. App loss cancels and aborts capture
and handoff tasks and clears the view/artifact list. At most eight current
materialized artifacts are retained, each with a bounded lifetime.

A referenced or materialized resource may intentionally remain independently
useful after its semantic origin disappears, but it cannot operate on or
reauthorize a replacement GUI target.

## 17. Terminal lifecycle

`TerminalGuard` owns raw mode, alternate screen, cursor, and mouse state.
Normal drop restores them, and the installed panic hook also invokes restore.
SIGINT and SIGTERM request orderly stop. SIGUSR1/SIGUSR2 detach and reattach
without changing application generation, discard bounded buffered input, and
recompute terminal size. External text retires the Crossterm reader, restores
the real terminal for the handler, then creates one reader on reattach.

The current live lifecycle run passed detach/event/reattach, four resizes, and
SIGTERM restoration with canonical input and echo. A current controlled panic
probe was attempted, but its unrelated Chrome fixture aborted before the panic
case; the RAII/panic path was therefore source-inspected rather than newly
requalified. SIGTSTP/SIGCONT is not implemented or tested.

```text
TERMINAL_STATE_RESTORATION=PARTIAL
```

Required future baseline: normal exit, SIGINT/SIGTERM, configured external
handler handoff, resize, and controlled panic restoration must pass. Suspend/
resume should be an explicit supported-or-deferred decision, not assumed.

| Resource | Current owner/bound | Cleanup | Gap |
| --- | --- | --- | --- |
| Event producer | Detached task per subscription; queue 2,048 | Receiver close wakes producer | Retain/join or otherwise observe task exit |
| Event queue | Current `EventSubscription` | Dropped with application view; overflow resync | Prove repeated overflow cannot starve operations |

## 20. Concrete negative/risk evidence

1. **Same-looking restart is not sameness.** A2 reused application, window,
   and control names, but A1 bindings were dead and A2 required generation 2.
   Future recovery must never reattach by those names.
2. **Transport recovery can choose by description.** The current reconnect
   path reconstructs with `app_selector`; duplicate exact names are not an
   application-instance proof. A fresh generation prevents old commands, but
   the intended current application still needs explicit recovery policy.
3. **External results can return into another GUI lifetime.** A modified
   candidate returned after A1 died and A2 appeared. The write was safely
   refused; this must remain a hard generation/locator/scope rule.
4. **Detached background work needs an owner.** Event sender closure ends the
   old producer, but no `JoinHandle` proves when it exited. Reconnect/shutdown
   should not rely on eventual task disappearance.
5. **Same-generation UI history is not bounded.** Command recency and focus
   history clear at application replacement but have no bound during unique
   surface churn.
6. **Non-idempotent uncertainty cannot be replayed.** Press, Toggle, and
   Activate may have taken effect even when transport lost the reply. Blind
   retry could duplicate or invert the action.

## 21. Current recovery behavior

- Target disappears: exact operation refuses or bounded observation becomes
  stale/unavailable; fresh current scene can continue.
- Window recreates: generation stays; exact locator and scope distinguish the
  replacement; fresh binding works.
- Application disappears: generation is invalidated, work cancelled, current
  controls become unavailable, and F5/`b` are offered.
- Application restarts: there is no silent rebind; explicit user retry opens a
  new generation.
- Bus disconnects: four automatic bounded attempts run; success opens a fresh
  generation, continued failure becomes read-only until explicit retry.
- Fresh authority: always comes from new enumeration/cache/scope/scene, never
  from a retained node, focus, name, index, or operation result.

## 22. Proposed minimal recovery model

Future v0.6 should use the existing identities:

```text
detect owner/transport loss
→ invalidate current ApplicationGeneration immediately
→ cancel and retire work owned by that generation
→ optionally rebuild the AT-SPI transport
→ enumerate public current applications
→ require exact surviving instance evidence or fresh user selection
→ open a new ApplicationGeneration
→ rebuild cache/scope/scene from scratch
→ user continues manually
```

Transport recovery and semantic reauthorization are distinct. Reconnecting a
D-Bus/AT-SPI transport may be automatic and bounded. Authorizing a current
application after all instance identities changed must not be automatic merely
because its descriptive name matches.

Safe failure remains valid: a continued transport outage may require a
GUI2TUI process restart or explicit F5, provided no stale action remains and
terminal/resources are restored.

## 23. Non-idempotent retry policy

Desired-state operations such as set text/value or request an exact Expanded
state may be retried only after fresh authority and fresh state prove the
desired mutation is still necessary and the public operation is safe.

`Press`, generic `Toggle`, and `Activate` are non-idempotent or effectful. An
interrupted result is **unknown**, not permission to replay. They must never be
automatically retried across transport or application generation changes.
Fresh application semantics may reveal the effect; otherwise the user chooses
a fresh current operation.

## 24. Proposed 1.0 runtime-continuity baseline

For an otherwise supported environment, 1.0 runtime continuity should require:

1. app-instance replacement immediately invalidates all old semantic
   authority;
2. fresh application and window authority can be reacquired without restarting
   the entire user task model;
3. late operation results, cancelled tickets, and old events cannot mutate,
   confirm, or overwrite a newer epoch;
4. repeated window/dialog/menu churn preserves current scope, fresh bindings,
   and safe focus while retained runtime resources stay bounded;
5. event queues are bounded and overflow forces fresh resynchronization rather
   than false event-derived truth;
6. external text and modality work cannot write or publish against a stale
   replacement, and owned artifacts have explicit cleanup/recovery;
7. supported AT-SPI interruption fails safely and follows an explicit bounded
   recovery contract without fuzzy application reattachment;
8. terminal modes restore on supported normal, signal, external-handler, and
   controlled abnormal exits;
9. interrupted non-idempotent operations are never blindly replayed;
10. fresh recovery never uses app/window/control name, geometry, PID,
    `RuntimeNodeId`, index, or timing coincidence as authority.

An evidence-driven future soak should be cycle-based first: a bounded number
of app generations, surface cycles, event overflows, operations, external
handoffs, and transport interruptions with resource samples. A modest wall-
clock run may supplement it, but elapsed time is not the architecture or the
success condition.

## 25. Optional and deferred runtime behavior

- Automatic short transport reconnect: **baseline candidate**, only with fresh
  semantic reauthorization policy.
- Transparent same-name app restart recovery: **not baseline**; explicit fresh
  user selection is safe and sufficient.
- Simultaneous control of many unrelated applications: **deferred**.
- Dedicated user-facing top-level window manager: **optional**, unless future
  evidence shows current focus/scope selection makes a baseline task
  unreachable.
- SIGTSTP/SIGCONT: **decision deferred to terminal lifecycle phase**.
- Very long unattended operation/background persistence: **not initial
  baseline**; bounded interactive continuity is required.
- Hour-scale soak and final performance thresholds: **1.0 integration**, after
  v0.6 establishes ownership and metrics.

## 26. v0.7 boundary

v0.6 owns correctness over time inside an otherwise supported runtime:
application/window/bus lifecycle, epoch isolation, queues, cancellation,
resource lifetime, and terminal ownership.

v0.7 owns whether and how an environment is supported: Wayland vs X11,
headless/SSH configuration, permissions, installation, session discovery,
package architectures, first-run/doctor behavior, and remote companion policy.
An AT-SPI interruption inside a supported session is v0.6; absence or
misconfiguration of AT-SPI in an environment is v0.7.

## 27. Architecture conclusion

**A — EXISTING AUTHORITY MODEL SUFFICIENT; BOUNDED RUNTIME HARDENING
REQUIRED.**

`RuntimeSessionId + ApplicationGenerationId + BackendLocator` already provide
the required authority epoch. `InteractionScope`, operation tickets, exact
scene bindings, fresh reads, and whole-view replacement compose correctly in
the tested restart, window, in-flight, event, external-edit, and bus-loss
cases. The remaining work is to make transport/application reauthorization
policy exact, make all background ownership and history bounds explicit, and
finish terminal/external lifecycle qualification.

No `RuntimeEpochId`, `SurfaceGenerationId`, runtime manager redesign,
multi-window manager, task runtime, or event-sourcing layer is justified.
